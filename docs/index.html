BatchSleuth

When a retrained model gets worse, BatchSleuth traces the regression to the training-data batches that caused it, tests repairs counterfactually, and promotes a model only if it passes safeguards.

    How it works

    Three independent signals, combined with robust z-scores. Each catches bugs the others miss.

    Influence for boosted trees

    LightGBM isn't differentiable, so it uses a leaf-local, BoostIn-style approximation: replay the boosting trajectory and measure how up-weighting each row moves its leaf values, and thereby the evaluation loss. The replay reproduces LightGBM's own leaf values to within 1e-8.

    Label quality

    Confident learning on 3-fold out-of-fold probabilities flags rows whose label the model confidently contradicts. The batch score is the fraction of flagged rows.

    Data validation

    Share of rows with values outside the trusted reference range catches zero-fills, sentinels and unit changes. PSI drift is shown in explanations but kept out of the score: natural source-to-source drift makes it fire on clean batches.

    Safeguarded promotion

    AUC non-inferiority (paired bootstrap CI), log-loss, calibration, worst-slice AUC, and a cap on data removed. Every model is an MLflow run tagged with its DuckDB dataset version.

    Run it yourself

    Runs on a laptop: about 1.2 GB peak RAM, 4 CPU threads, and around 25 MB of data. No GPU or cloud needed.

    # clone, install into a local virtualenv, run the full story (~40 s)
git clone https://github.com/aditib03/batchsleuth.git && cd batchsleuth
make setup
make demo
# interactive API docs at http://127.0.0.1:8000/docs
make serve
# reproduce the benchmark on this page
make bench
